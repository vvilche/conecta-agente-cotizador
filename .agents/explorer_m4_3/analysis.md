## 1. Executive Summary & Testing Strategy

The **Supervisor Human-in-the-Loop Web Console** (Milestone 4) serves as the primary authorization gateway and audit control plane for the *Sistema Agenticio Inteligente Ecosistémico para Odoo ERP*. 

### Core Safety Invariant: 0% Auto-Execution Gate
No specialized agent in `swarm_engine` (`RFQProspeccionAgent`, `CotizacionInventarioAgent`, `OperacionesPresupuestoAgent`, `EstadosPagoAgent`, `GestionDocumentalAgent`, `ConciliadorContableAgent`) can directly mutate the production or mock Odoo database. All proposed operational actions are staged as `DraftAction` records with initial status strictly defaulting to `"pending_vobo"`.

The test suite in `tests/test_supervisor_ui.py` must rigorously verify:
1. **Queue Management & Filtering**: Correct ingestion, ordering, retrieval, and multi-criteria filtering of pending drafts.
2. **`approve_draft` Workflow**: Verification that approving a draft invokes `OdooClient.commit_draft` / `OdooClient.create`, mutates Odoo DB, transitions state to `"approved"` or `"committed"`, and generates an immutable audit log entry.
3. **`reject_draft` Workflow**: Verification that rejecting a draft strictly prevents Odoo DB mutation, transitions state to `"rejected"`, and generates an immutable audit log entry.
4. **REST API Endpoints Integration**: Full endpoint verification for `GET /api/drafts`, `GET /api/drafts/<id>`, `POST /api/drafts/<id>/approve`, `POST /api/drafts/<id>/reject`, `GET /api/audit-logs`, and `GET /api/stats`.
5. **0% Auto-Execution Invariant Enforcement**: Empirical proof that unapproved drafts in the queue CANNOT affect Odoo DB until an explicit VoBo payload signature (`supervisor_id`) is passed.

|---|---|---|
| **Unit: Queue & Filtering** | `src/supervisor_ui/console.py` | Draft registration, list filtering by `agent_name` & `status`, timestamp sorting, `get_draft_by_id`, `DraftNotFoundError`, queue metrics. |

| **Invariant: 0% Auto-Execution** | System-wide (`swarm_engine` + `supervisor_ui` + `odoo_ecosystem`) | Baseline Odoo record count stability while drafts sit pending in queue; mutation execution strictly contingent on explicit VoBo approval signature. |
| **Adversarial & Edge Cases** | System-wide | Race condition safety, invalid payload types, malformed supervisor IDs, security credential masking in API and logs. |

class TestZeroAutoExecutionInvariantM4:

    def test_unapproved_drafts_in_queue_cannot_affect_odoo_db(self, supervisor_console, mock_odoo_server, sample_drafts):
        """
        MANDATORY INVARIANT VERIFICATION:
        Verifies that staging drafts in SupervisorConsole queue does NOT alter Odoo database state
        until explicit supervisor approval signature is received.
        """
        initial_counts = {
            model: len(mock_odoo_server.search_read(model, []))
            for model in ["crm.lead", "sale.order", "account.move", "res.partner", "crossovered.budget.lines"]
        }

        # Ingest all drafts into queue
        supervisor_console.ingest_swarm_drafts(sample_drafts)

        # Confirm queue has drafts
        assert supervisor_console.get_stats()["total_drafts"] == 6

        # Verify DB counts remain 100% unchanged
        for model, initial_c in initial_counts.items():
            current_c = len(mock_odoo_server.search_read(model, []))
            assert current_c == initial_c, f"Zero Auto-Execution Violation! Model '{model}' mutated prematurely."

        # Reject a draft
        supervisor_console.reject_draft(sample_drafts[1].draft_id, supervisor_id="sup_test")

        # Verify DB counts STILL unchanged
        for model, initial_c in initial_counts.items():
            current_c = len(mock_odoo_server.search_read(model, []))
            assert current_c == initial_c, f"Zero Auto-Execution Violation! Model '{model}' mutated upon rejection."

        # Approve 1 draft (crm.lead)
        supervisor_console.approve_draft(sample_drafts[0].draft_id, supervisor_id="sup_test")

        # Verify ONLY crm.lead count incremented
        assert len(mock_odoo_server.search_read("crm.lead", [])) == initial_counts["crm.lead"] + 1
        assert len(mock_odoo_server.search_read("sale.order", [])) == initial_counts["sale.order"]
